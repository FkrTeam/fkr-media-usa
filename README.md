# FKR MEDIA USA

A cinematic, WebGL-driven site for a creative technology and digital media
agency. Vite + vanilla ES modules + Three.js + GSAP. No framework.

Four routes — **Home · Services · About · Contact** — served as four real
static documents, then taken over by a client router that keeps the WebGL
context alive across navigation.

The creative concept, colour, type, spacing and motion rules are documented in
**[DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)** — read that first if you are changing
anything visual.

| `npm run preview` | Serves the built site on `:4173` |

Useful URL flags:

- `?intro=skip` — bypass the opening film. Handy for QA and for deep links.

### Deployment — set the base first

**This is the one setting you must get right.** The site ships four real
documents in nested folders, so asset and link URLs have to be absolute —
which means the build has to know where the site will live.

Open `.env` and set two lines:

```bash
VITE_BASE=/fkr-media-usa/
VITE_SITE_URL=https://fkrmediausa.com
```

| Where you are uploading to | `VITE_BASE` |
|---|---|
| `https://example.com/` | `/` |
| `https://test.esd.ms/fkr-media-usa/` | `/fkr-media-usa/` |

Then `npm run build` and upload the **contents of `dist/`** into that folder.

`VITE_BASE` flows to three places at once — Vite's asset URLs, the internal
links written by `scripts/pages.mjs`, and `<html data-base>`, which the
router and the asset helper read at runtime. Nothing is hardcoded twice.

`VITE_SITE_URL` is only used for canonical, Open Graph and JSON-LD URLs, and
it deliberately ignores the base. A staging copy at
`test.esd.ms/fkr-media-usa/services/` still declares its canonical as
`https://fkrmediausa.com/services/`, which is what stops the test site being
indexed as a duplicate of the real one.

If you upload a build made for `/` into a sub-folder, every stylesheet,
script and image 404s and the page renders as unstyled text. That is the
symptom to recognise.

**Do not add an SPA catch-all rewrite.** The server only needs to resolve
`/services` to `services/index.html`, which nginx (`try_files $uri
$uri/index.html`), Apache (`DirectoryIndex`, on by default), Netlify, Vercel
and S3 + CloudFront all do already. A catch-all would serve the home
document at every URL and destroy the per-route metadata.

### Shell vs page

| Built once per session | Rebuilt per route |
|---|---|
| Renderer, render loop, camera | `<main>` content |
| Cursor, navigation, menu, footer | Split text, ScrollTriggers |
| Router, intro film | Logo marquee, contact form |

`src/animations/page.js` owns that boundary: `mountPage` wires whatever the
current document declares, `unmountPage` kills every page-scoped trigger,
tween and listener before the router replaces the markup.

Because `renderPage()` runs every renderer and each one no-ops when its host
element is absent, a route gains a shared block by declaring the markup and
nothing else — no registration, no per-page wiring. That is how the same
client and review data reaches four routes:

| Block | `/` | `/services` | `/about` | `/contact` |
|---|:--:|:--:|:--:|:--:|
| Client marks (42) | strip | strip | wall | strip |
| Client reviews (3) | ● | ● | ● | — |
| Numbers | ● | ● | ● | ● |

The contact route carries both the numbers and the strip *after* the form,
not before them: someone who reached that page is already trying to make
contact, and proof placed in front of the field they came to fill in would
work against them. Verified over
twelve consecutive route changes: ScrollTrigger counts return to exactly the
same value per route, and geometry / texture / program counts do not move.

### Caching on the server

Dropping `dist/` on a host and seeing an old logo or an old stylesheet is
almost always one of two things, and only one of them is a real problem.

**The bundle is already safe.** Vite writes a content hash into every
filename it emits — `main-oCdSShk5.js`, `style-BYo50kM4.css`,
`inter-latin-Dx4kXJAl.woff2`. A changed file gets a different name, so a
cached copy can never be the wrong copy. Do not add cache-busting here; it
would throw away the one thing that already works.

**Two things are not hashed**, and both are handled:

| | Risk | Handled by |
|---|---|---|
| `*.html` | Stable name, changing contents — and it names the hashed bundle, so a stale document pins the site to an old build | `no-cache, must-revalidate` in `public/.htaccess`; the router also fetches routes with `cache: 'no-cache'` |
| Everything copied from `public/` (logos, brand marks, intro film, favicon) | Path never changes, so a replaced file keeps serving the old bytes | `?v=<build id>` on every URL |

The build id is a **hash of the bytes in `public/`**, computed in
`scripts/pages.mjs` and stamped onto `<html data-build>`. `asset()` reads it
back and appends it to every runtime request; the few asset paths written
directly into `_shell.html` get the same value through the `{{v}}` token.

It is deliberately not a timestamp. A build that changes nothing produces
the same id, so visitors keep their cached copies instead of re-downloading
400 KB of identical logos on every deploy — while replacing a single image
changes the id and invalidates the set. Verified both ways: two consecutive
builds of unchanged content give the same id, one altered byte changes it,
and reverting that byte restores the original id.

`public/.htaccess` ships inside `dist/` and applies to the directory it
lands in, so a sub-directory deploy needs no server-wide change. It is
Apache-only. On nginx the equivalent is:

```nginx
location ~* .html$            { add_header Cache-Control "no-cache, must-revalidate"; }
location ~* .(js|css|woff2)$  { add_header Cache-Control "public, max-age=31536000, immutable"; }
location ~* .(png|jpe?g|webp|svg|ico|mp4|webm)$ { add_header Cache-Control "public, max-age=2592000"; }
```

If a host ignores both, the `?v=` query still forces every public asset to
be refetched after a content change — that part needs no server cooperation
at all. Only the HTML documents genuinely depend on a response header, and
a hard refresh covers them until one is set.

### Who owns the scroll position

Three things want to decide where a new page starts, and they had to be put
in order — the symptom otherwise is a route opening halfway down.

1. **`scroll-behavior: smooth`** on `<html>` (styles/base.css) turns a bare
   `scrollTo(0, 0)` into a ~700ms animation. During a route change that
   animation is measured against the *outgoing* document and is still running
   when `<main>` is replaced, so it ends wherever the new height leaves it.
   `resetScroll()` passes `behavior: 'instant'` explicitly, which overrides
   the stylesheet. The smooth rule is kept because in-page anchors want it.
2. **ScrollTrigger** records each document's scroll offset and restores it on
   `refresh()` — which `onEnter` calls right after mounting. So the reset runs
   twice: once at the swap, once after the refresh.
3. **`history.scrollRestoration`** is set to `'manual'`, otherwise a reload
   lands where the visitor left off — behind a 40-second intro film.
   Assigning it directly does **not** hold: ScrollTrigger reads the original
   value when its module loads and writes it back after every refresh, so it
   is set through `ScrollTrigger.clearScrollMemory('manual')` instead, which
   updates ScrollTrigger's own copy as well.

A URL with a hash is exempt from all of it. Deep links are resolved by
`scrollToHash()` *after* mount, not by the browser: most sections are built
from data after the document parses, so at the moment the browser tries to
resolve `/services/#seo` natively the target does not exist yet and it gives
up at the top. Both the router and the first load call the same function.

### One canvas, one loop

There is a single `WebGLRenderer` and a single `requestAnimationFrame`, both
owned by `Experience`. The loop stops entirely when the tab is hidden. UI code
never touches Three.js — it moves values on `experience.state` (scroll,
pointer, intensity, accent) and the render layer reacts.

Each frame does exactly one DOM read (the work plane's rect) and no DOM
writes, so the render loop can never cause layout thrash.

### Rendering order

```
clear → background (orthographic) → signal field (perspective)
      → work plane (DOM-pixel camera) → composite pass
```

`autoClear` is off; the loop clears once and layers the passes by hand.

## Brand

Both brand constants are sampled from the supplied artwork in
`public/brand/fkr-media-usa-logo.png` — **`#EE473D`** (87% of its opaque
pixels) and **`#050505`** — and are defined once in `styles/tokens.css` and
`src/data/brand.js`. Nothing hardcodes a brand colour anywhere else, CSS,
JavaScript or GLSL.

The logo is never recoloured or redrawn. Because its MEDIA wordmark is set in
black, it appears in two sanctioned presentations, both cut from the original
file by `npm run brand`:

- the **red FKR mark** in the navigation, preloader and favicon, on near-black
- the **full lockup** on a warm off-white plate in the footer and OG card

See [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md) §2 and §9 for the palette, the
red budget and the logo rules.

### The contact form is not connected

While `endpoint` is null the form validates, then reports plainly that it is
not connected, keeps everything the visitor typed, and offers a pre-filled
mailto instead. It never shows a success state for a message that went
nowhere. Point `endpoint` at any JSON-accepting URL — a form service, a
serverless function, your own API — and it starts working.

## The opening

1. Black. The FKR mark fades up.
2. A preloader tracks *real* resource completion — fonts, shader compilation,
   the film's first bytes. The percentage only moves when something finishes.
3. The film fades in and plays for 40 seconds, with a timecode, a progress
   line and a discreet **Skip intro** control that appears after 2.5s
   (`Esc` also works).
4. Five seconds before the end, the hero materials are pre-compiled
   (`renderer.compile`) so the handoff costs nothing.
5. The WebGL world rises *behind* the film, the field wipes in from the
   horizon, the film fades and lifts away, and the hero lines, navigation and
   standfirst arrive on overlapping timings. There is no cut anywhere.

The film is never required. If the source fails, autoplay is blocked, or it
has not reported itself playable within 9 seconds, a generated typographic
title sequence runs instead and hands off identically. `sessionStorage`
remembers that the film has been seen, so it plays once per session — not on
every navigation.

### Replacing the film

`public/media/` currently holds a **procedurally generated placeholder**
(`npm run intro` regenerates it). Drop the real brand film in with the same
names and everything works unchanged:

```
intro-desktop.webm / intro-desktop.mp4    1920×1080
intro-mobile.webm  / intro-mobile.mp4      960×540
intro-poster.jpg                           first frame
```

Sources are declared in `site.js` and chosen by viewport, so a phone never
downloads the desktop file.

## Performance

- One WebGL context, one render loop, paused when the tab is hidden.
- DPR capped at 1.5 (1.25 on low-tier devices).
- Adaptive quality: frame time is sampled over a two-second window and the
  render scale steps down (never below 60%) if the budget is blown, then
  recovers. On a software renderer it drops immediately — which is the point.
- Three device tiers set the particle budget: **high** 45,000 points ·
  **medium** 60% · **low** 30%. Post-processing is disabled below high tier.
- The signal field is a single draw call.
- Staged loading — nothing is fetched before it is needed:

  | Stage | Contents | When |
  |---|---|---|
  | 0 | Fonts, logo, navigation, critical CSS | Blocks the preloader |
  | 1 | Film metadata, hero shaders (pre-compiled) | Blocks the film |
  | 2 | The current route's own media | On scroll approach |
  | 3 | The other route documents | Idle, or on link intent |

- GLTF / DRACO / KTX2 / Meshopt loaders are dynamically imported and only
  fetched if a `.glb` is actually registered — they are not in the entry bundle.
- Build output: `three` ~518 kB raw (~130 kB gzipped) in its own chunk,
  `gsap` ~70 kB, app ~102 kB, CSS ~28 kB, fonts ~175 kB.

To add 3D models, register them in a stage and drop DRACO/Basis binaries into
`public/vendor/draco/` and `public/vendor/basis/`.

## Accessibility

- Every text token clears WCAG AA (4.5 : 1) against both the `#050505` ground
  and the brightest point of the ambient ember. Brand red is 5.4 : 1 on the
  ground and is still restricted to accents — never body text.
- Full keyboard support: skip link, visible 2px focus rings that are never
  removed, logical tab order, `Esc` closes the menu and the film.
- Service rows and the work stage express hover state through
  `:focus-within` as well, so keyboard users see the same feedback.
- The mobile menu marks the page behind it `inert`, locks scroll, and returns
  focus to its trigger on close.
- `prefers-reduced-motion: reduce` skips the film, restores split text,
  stops the marquee, drops WebGL amplitude to 35%, disables post-processing
  and collapses every GSAP duration.
- The custom cursor is only created on `(hover: hover) and (pointer: fine)`
  and is parked off-screen until the pointer actually moves.
- Semantic landmarks, one `h1`, sequential `h2`/`h3`, labelled sections.
- The intro film is muted, decorative and carries no speech, so it needs no
  captions; it can be dismissed at any time by button or keyboard.

## Resilience

Nothing in this build can leave a visitor stranded:

- **No WebGL** → `no-webgl` on `<html>`, a static ember-on-black stage
  replaces the canvas, and the work section falls back to a real `<img>` stack.
- **Context lost** → the same fallback is applied live.
- **Film fails / autoplay blocked** → generated title sequence.
- **A texture fails** → that plane degrades to neutral charcoal; the rest is untouched.
- **A resource hangs** → every item has a 14-second timeout and resolves `null`.
- **The boot throws** → `main.js` removes the preloader, unlocks scroll and
  reveals the page.
- **No JavaScript at all** → the document is complete and readable; the
  overlays never appear.
